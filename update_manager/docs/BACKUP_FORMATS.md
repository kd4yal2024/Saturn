# Saturn Backup Formats

REM-0302 separates three different recovery needs. Their archives are not
interchangeable and none should be described merely as a “full backup.”

## 1. Portable settings backup

Endpoint: `GET /backup_settings`

Filename: `saturn-settings-YYYYMMDD-HHMMSS.tar.gz`

Archive root and format:

```text
saturn-settings-v1/
├── manifest.json
├── saturn-state/
│   ├── state-schema.json                 (when present)
│   ├── custom_scripts.json               (when present)
│   ├── remote_settings.json              (when present)
│   ├── remote_profiles.json              (when present)
│   ├── repo_root.txt                     (when present; review on import)
│   ├── update_policy.json                (when present)
│   └── saturngo_update_policy.json       (when present)
├── custom-scripts/
│   └── <registered operator files only>
└── clients/
    ├── pihpsdr/*.props
    └── deskhpsdr/*.props
```

`manifest.json` has format `saturn-settings-backup`, schema version `1`, the
creation time, Saturn Go build commit, portability/sensitivity notices, and a
sorted file list. Each file record contains its REM-0301 inventory ID, archive
path, byte size, original permission mode, and SHA-256 digest. It also embeds
the explicit exclusions and states that REM-0303 transactional restore is
required.

Only regular files are accepted. Symlinked state, property, or registered
script files fail the backup. An individual file is limited to 16 MiB and the
complete selected payload to 128 MiB. Staging uses a private mode-0700
directory; archive files are staged as mode 0600 and removed after the stream
ends.

Packaged scripts with registry version `custom-default` are regenerated by the
installer and their content is omitted. A registry entry for another script
is treated as operator-authored and its matching content is required.

The settings archive always omits:

- Saturn/Linux credentials and initial-login recovery material;
- remembered-device cookie secret and TLS/SSH private keys;
- Tailscale, NetworkManager, Wi-Fi, machine, and hostname identity;
- boot/LCD/front-panel and device provisioning configuration;
- deployment transactions, state-migration backups, and logs;
- source repositories, installed releases, caches, and staging;
- the contents of FPGA flash.

The archive is private operator data, not a support bundle. Custom scripts and
radio property files may contain sensitive values. Review repository paths,
protocol/IP settings, PA/calibration, drive, antenna, ADC, microphone, and
transmit settings before importing to different hardware.

Settings import is intentionally unavailable in REM-0302. REM-0303 must first
validate the archive, schema, digests, paths, ownership, permissions, and free
space, then stage and activate it transactionally.

## 2. Source repository backup

Endpoint: `GET /backup_source`

Compatibility endpoint: `GET /backup_full` returns the same source archive so
old bookmarks continue to work. New UI and documentation do not call it a full
backup.

Filename: `saturn-source-YYYYMMDD-HHMMSS.tar.gz`

Content: the complete active mutable Saturn repository directory, including
`.git`, tracked source, untracked files, and build products that currently
exist below that root. Content outside the repository is omitted.

This archive is intended to preserve source and deliberate local changes. It
does not contain Saturn settings, credentials, installed immutable releases,
OS/network/boot state, client settings outside the repository, or FPGA flash.
Because Git configuration or untracked files might contain private data, treat
it as sensitive and inspect it before sharing.

The historical `/restore_full` route is now labelled **Legacy Source
Restore**. It accepts only a Saturn repository-shaped archive and still uses
in-place `rsync --delete`; it is not transactional. REM-0303 owns replacement
of that restore path.

## 3. Installed immutable release backup

List endpoint: `GET /backup_releases`

Download endpoint: `GET /backup_release?commit=<full-40-character-commit>`

Filename: `saturn-release-<full-commit>.tar.gz`

Content: one real direct child of `/opt/saturn/releases` (or the configured
release root) with a full hexadecimal commit name and an existing
root-level `release-manifest.json`. The complete immutable release directory is
archived, including binaries, web assets, its release/component policies, and
the checksum manifest created by the release builder.

The export endpoint relies on the root-owned immutable-release installation
boundary and requires the manifest to be present; it does not replace the
release installer's full checksum validation.

The archive omits mutable settings, credentials, repositories, network/boot
state, deployment transactions, and every other installed release. It is a
release payload, not a radio/appliance backup. Restoring and installing a
release remains a local validated release-manager operation until REM-0303
defines archive import.

## 4. Whole-disk disaster recovery

Saturn Go does not image, clone, enumerate, or wipe storage devices. Whole-disk
work remains a manual local-console procedure because selecting the wrong
device is destructive and browser disconnection cannot safely own the job.

A disk image is for same-device disaster recovery. It contains whatever the
imaging tool reads from that device, including credentials and unique identity,
so protect it accordingly. It does not capture browser-side remembered-device
cookies, external services, another disk, or verified FPGA flash contents.

Before capture:

1. Prefer a powered-down or otherwise quiesced source filesystem.
2. Record source model, serial, size, transport, partitions, kernel, Saturn
   commit/release, FPGA version/date, and the image checksum.
3. Verify the destination has sufficient capacity and is not the running disk.
4. Test restoration on spare media before treating the image as recoverable.

Before distributing an image to another operator, use the image-factory seal
workflow. The recipient's first boot must generate unique machine/SSH/TLS,
administrator, hostname, and Tailscale identity. A raw image of an operating
radio must never be distributed as-is.

See the Operations Runbook for the current manual commands and safety checks.
