# PureSignal milestone 1 — source trace and interface review

Prepared for Jerry and DarkOverLord by SilverForge, 2026-10-12.

## Outcome and scope

**The next work is host-side implementation and offline validation, not an FPGA replacement.** P2 already configures and transports a paired reference/feedback stream into Bridge's WDSP TX engine. Direct XDMA currently prohibits PureSignal and its acquisition parser accepts only the ordinary DDC6 RX layout. Those are concrete implementation gaps, not evidence that the FPGA lacks feedback hardware.

Keep the reported installed **1.31.002 / `0x53460004`** as the intended target. The source establishes a plausible unchanged-firmware route, but does not yet establish that the exact RXC1 routed design preserves every synchronization property under loss/backpressure. That requires matching the frozen revision-4 source evidence and then offline pair-integrity replay/simulation. No new firmware is justified by this audit. If that evidence exposes a missing hardware guarantee, document it separately before proposing a firmware change.

This deliverable is a design/source audit, not a production enablement or a PureSignal qualification. No G2 connection, service restart, deployment, register access, RF transmission, or installer change was performed. Existing normal-TX approval and RX soak results remain separate from PS correction, IMD accuracy, and overload qualification.

The concrete deliverables are this report, [proposed interfaces](contracts.ts), [native ABI declarations/storage](native-abi.h), and a [read-only source-contract checker](verify-source-contract.py). None is wired into production. Intended result remains working correction on **both** Bridge backends, trustworthy measurements, and PS Monitor, Distortion Analyzer, and AmpView as three dockable panels.

## 1. Feedback paths, format and synchronization

### FPGA and P2 hardware owner

The checked-in TX block design connects a registered multiplier output to `TXSamplesToRX`, with a 16-bit register at the 122.88 MHz clock. A related branch reaches the DAC selection/offset-binary conversion. Top-level `Transmitter/TXSamplesToRX` connects to `Receiver/tx_samples`. The DDC input mux selects ADC1, ADC2, test source, or TX samples. [TX tap][F1], [top connection][F4], [DDC mux][F2]

**Do not conflate three different indices:** P2 source `0` is physical ADC1, P2 source `1` is physical ADC2, P2 source `2` is TX samples. P2_app converts these to register selection codes `0`, `1`, and **`3`** respectively; register code `2` is the test source. The current Bridge config is DDC0=P2 source0 feedback, DDC1=P2 source2 reference. [P2 mapping][S1], [hardware enum/registers][S5]

`configure_puresignal_feedback()` requests enable mask1, DDC0/1 both 192 kHz and 24-bit, and sync DDC1 to DDC0. P2_app's actual command decoder recognizes the even/odd sync mask, enables the odd partner, marks the even channel interleaved, and encodes even rate7/odd rate3. Thus DDC0/1 rate fields are `0x1f`, not two independent ordinary channels. The TX high-priority state sets both phase words to TX frequency. The source also routes the even LO IQ to its odd partner; independent-LO debug must remain disabled (rate register bit30). [Bridge config/tuning][S9], [decoder][S16], [DDC LO wiring][F5], [debug control][S5]

DDCMux emits the even stream then odd stream, repeating the pair, with a header containing the rate word and an `0x8000` upper marker. Each sample word carries 48 IQ bits in a padded 64-bit transfer. After configured byte swapping, P2_app copies the first six bytes of each DMA word, preserves pair order, and sends a DDC0 UDP packet with 238 IQ entries: **119 reference/feedback pairs**, about **0.620 ms** of 192k sample time. Packet size is 1,444 bytes. The packet's eight-byte timestamp is explicitly zeroed; its u32 sequence counts outbound packets, not FPGA acquisitions. [Interleaver][F3], [P2 packetizer][S2]

Bridge sign-extends big-endian signed24 I/Q and divides by `2^23=8,388,608`. Values span `[-1, 1-2^-23]`. Its split transforms `[feedback I,Q, reference I,Q]` into two interleaved f64 arrays. The normal parser checks packet/payload lengths but does not enforce PS-specific 24-bit/rate/config/generation validity. [Parser/split][S3]

`rx_thread` diverts DDC0 into `TxCommand::PureSignalFeedback` during PS TX, bypassing RX AGC/demod/audio. The command contains two newly allocated vectors, a packet sequence, and an arrival `Instant`; it does **not** carry acquisition generation, TX epoch, source rate, FPGA time, route, clipping evidence, or scaling identity. The TX worker feeds it while keyed. On unkey it clears PS MOX before stopping TXA and restores the normal RX DDC configuration. [Ingress][S4], [TX lifecycle][S12]

The existing sequence helper counts forward missing packets but still feeds discontinuous data and accepts duplicates/reordered packets. A packet-arrival timestamp is useful for age/queue delay, **not** RF alignment. Source wiring plus interleaved order establishes the intended pairing mechanism, not proof against silent one-sided sample loss. Those cases need fixtures and matched RXC1 hardware-source analysis.

### Direct XDMA path and missing work

Direct uses DDC6 at 384k for ordinary receive. Its parser matches one exact rate header and then rejects any other active channel layout, even though `analyse_rate_word()` can calculate interleaved counts. Configuration writes rate register **`0x100c`**, input selection **`0x1010`**, and DDC6 tune **`0x0018`**. Startup/recovery assumes DDC6-only. [Direct acquisition][S6]

`XdmaTxRadio::configure_puresignal_feedback()` returns unsupported. Direct backend startup forces PS off, PS setting actions force it off, and PS status events are ignored. Consequently adding a generic rate parser or changing a UI checkbox cannot enable correction. [Direct TX adapter][S7], [Direct policy][S17]

Proposed adapter uses the existing sole acquisition owner, reserves DDC0/1 at192k during authorized TX, selects physical ADC feedback and register source3 TX reference, and sets both tunes to TX frequency/shared LO. A TX-only DDC0/1 layout is `0x1f`; if DDC6 is retained concurrently the expected layout must explicitly include its rate4 field (`0x0010001f`). **This is a proposed layout, not a command to execute.** Decide concurrent RX policy before implementation; do not inadvertently publish paired feedback as ordinary receive or add a second DMA reader.

The owner must perform quiesce/configure/readback/reset/resume as one acknowledged generation transition, demux complete even/odd pairs across arbitrary DMA chunk boundaries, and restore prior DDC6 tuning/rate/ADC/attenuation on release/cancel/error. Recovery must restore the active layout, not silently revert to DDC6 while PS remains marked active. Known FIFO loss/framing failure invalidates the pair generation; a synthesized host ordinal cannot prove unknown hardware samples were retained.

### Signatures and buffer sizes

`native-abi.h` declares the exact interfaces checked against the pinned generated public header. Core calls are:

```c
void pscc(int channel, int size, double *tx, double *rx);
void GetPSInfo(int channel, int *info);
void GetPSDisp(int channel, double *x, double *ym, double *yc, double *ys,
               double *xm_cor, double *ym_cor, double *xa_cor, double *ya_cor,
               int *nsamps_out, int *cpts_out, double *phs_ref_deg_out);
double SetPSTXDelay(int channel, double delay_seconds);
```

| Buffer/call | Verified unit and capacity |
| --- | --- |
| `pscc size` | Complex IQ pairs **per stream**, not number of doubles; Bridge feeds1024 pairs/5.333ms at192k |
| `tx`, `rx` | Separate owned **mutable** arrays of2048 doubles each, `I,Q,I,Q…`; native delay processing modifies input arrays in place |
| `GetPSInfo` | Caller storage16 C ints, ABI32-bit; retain all16 raw values |
| `GetPSDisp x,ym,yc,ys` | Each allocate4096 doubles; collection has16 buckets ×256 samples; `nsamps_out` initially0, then4096 at this pin |
| `xm_cor,ym_cor,xa_cor,ya_cor` | Each allocate512 doubles; `DISP_PTS=512`; no length arguments to protect caller storage |
| Count outputs | C `int*`; reject returned counts outside verified capacity before exposing data; this post-check does **not** protect against a wrong linked ABI |
| Phase-reference output | `double*`, degrees; correction phase output `ya_cor` also degrees |
| Display storage payload | 18,432 doubles =147,456 bytes, plus counts/reference/alignment; allocate once, not per poll |

The ordinary Bridge TX channel uses512 mic samples at48k, DSP block2048 at96k, output192k, and2048 output IQ pairs per exchange. Those are distinct from PS input blocks and the4096 calibration collection. `TXA.c` applies `xiqc` before output resampling. Calls and lifetime transitions must be serialized on the TX controller; native internal locks do not make concurrent channel destruction safe. Capture analyzer input before `pscc` mutates arrays. [Saturn wrapper][S8], [public header][W2], [native implementation][W1], [TXA order][W3]

### Scaling and delay

DDC normalization is signed24/8,388,608 for both streams. Outbound DUC uses signed24 with clamping and multiplication by8,388,607; both backends use that packing path. Neither the RF detector watts nor LP700 watts is a PS IQ scaling constant. `SetPSHWPeak(0.6121)` sets native internal inverse scale `1/peak`; this is a **configured reference-return magnitude for normalized TXA unity**, not calibrated RF power and not proof of the current firmware's exact loop gain.

Current initialization requests feedback rate192000, HW peak0.6121, MOX settling0.2s, TX delay150ns, loop delay0s. It ignores `SetPSTXDelay`'s return. Positive delay delays reference; negative delay delays feedback. The pinned delay code quantizes to `L=round(1/(20ns*rate))`; at192k, L260 yields about20.032ns increments. A150ns request therefore computes approximately**140.224ns** of relative delay at that rate, which must be confirmed by the actual native return, not hard-coded into telemetry. This is requested/implemented relative alignment, **not end-to-end RF latency**. Rate changes recreate delay objects, so reapply delay after rate setup. [Initialization][S8], [delay][W6], [native setters][W1]

Existing auto-attenuation uses feedback140–165 as its hold band, reference152.293,15dB large steps, and0–31dB bounds. Preserve that as current behavior, not a calibrated power target; changing it needs native/route-specific evidence. Existing status can show “Correcting” for an old curve while a new calibration is pending/rejected. New telemetry must keep calibration validity, applied-reported state, and raw faults separate. [TX worker][S12], [native diagnostics/state machine][W1]

AmpView needs particular care: code computes `x=rx_scale*envRX`, `ym=normalizedTX/x`, and `yc+i*ys` as the **inverse** relative phase (`TX−RX`). These are normalized/inverse calibration coordinates, not automatically an amplifier gain/phase trace. Magnitude preparation can also limit the RX envelope to a forced-slope bound: these are calibration-conditioned points, not unmodified raw RF measurements. Preserve the native arrays and declare the transform: normalized input=`x*ym`, normalized output=`x`, measured gain=`20*log10(1/ym)`, measured phase=`-atan2(ys,yc)` in degrees with an explicit common reference; omit nonpositive/nonfinite/near-zero undefined points. Correction gain=`20*log10(ym_cor)`; phase=`ya_cor`, already unwrapped/centered by native code, with `phs_ref_deg` retained. These are **normalized relative curves**, not absolute PA gain or external calibration. Validate the convention using known gain/phase replay before shipping labels. [Native curve construction][W1]

## 3. Proposed shared controller and telemetry contract

The standalone [TypeScript definitions](contracts.ts) specify internal pair descriptors, commands/results, native/display products and browser telemetry. They are review interfaces; exact wire serialization/registration is deferred. Existing P2 wire packets remain unchanged. Keep legacy TCI text values for compatibility, add versioned PS telemetry rather than assigning new meanings to old scalar messages. Current publication has no product timestamps, validity or raw16 vector. [Legacy status][S19]

### Controller and adapter boundary

`FeedbackPairBlock` must carry boot ID, backend, FPGA/native identity, acquisition generation, TX epoch, config/route ID, equal sample count/rate/scaling, I/Q order, continuity evidence, source ordinal/time basis, and observed monotonic time. Hardware ticks are nullable. P2 timestamps are zero; XDMA rate headers lack sample sequence/time. Use explicitly **stream-relative** ordinals only while continuity is known. Arrival timestamps never imply FPGA time or RF alignment.

Runtime admission rejects unequal arrays, nonfinite values, wrong format/rate/route, stale generation/epoch, one-sided blocks, stale delivery, duplicates/reorder and known loss. Never silently trim to the shorter vector. On discontinuity discard partial assembly and invalidate the calibration generation. Count rejected blocks and their reasons. Scope every solution to firmware/native identity, band/frequency, drive setting, route/coupler, ADC, attenuation, delay and sample format. Any incompatible change invalidates old curves; no automatic restore across those changes.

Use one preallocated pair pool and a dedicated bounded ingress, not the unbounded TX control-command channel. Initial review proposal: four1024-pair block slots (~21.33ms sample backlog), bounded partial-packet assembly, nonblocking producer, drop/reject **whole pairs** on exhaustion, and separate counters for queue overrun/known transport gaps/unknown acquisition loss. The queue bound is a starting design budget to validate on ARM, not an asserted performance result. Cancel/unkey/controller loss has priority over pair draining; every dequeued block is revalidated against current epochs.

SetPSMox follows already-authorized TX state; PS configuration, calibration request, opening a panel, subscribing, reconnecting, and changing route must **never key RF**. Before stopping/recreating TXA, clear PS MOX and retire all old-generation callbacks/queues. A feedback/clipping/solution fault must not silently restart adaptation on the next received packet. Document and replay-test the chosen bypass/controlled-unkey policy; an RF-safe level envelope is a later qualification, not a guarantee from this audit. External P2 client ownership exposes read-only/unavailable status and must not create a second correction loop.

Every product has boot/generation/config ID, product sequence, observed and published monotonic times, optional synchronized UTC, source capture interval when available, age, freshness threshold, validity and machine-readable reasons. Null means unavailable/invalid, not zero. **M2 correction:** age at publication plus elapsed time since receipt omits transit queue delay and is not a freshness certificate. A nonce-matched, boot/connection-scoped round-trip probe provides a conservative server-clock upper offset; current maximum age is computed from the observation time with an oscillator-error allowance. No live bound means timing unverified, never fresh. Reconnect or a detected stall retires the bound and requires a fresh probe. Preserve last-good curves separately as visibly historical, not in a `valid` current product.

Proposed status publication ceiling5Hz; both plots2Hz per controller, shared by all viewers. UI freshness thresholds initially600ms status/1500ms plots; these are presentation budgets, **not** replacement TX safety timers. Aggregate subscriptions across docked/popout windows. Stop optional FFT/display harvesting when no viewer needs it; keep authorized correction running. FFT, plotting transforms and JSON serialization run off acquisition/control-critical paths. Bounded latest-product mailboxes can replace old plots; never block DMA on a slow viewer.

Native `GetPSDisp` has no generation/calibration counter/timestamp. `GetPSInfo` and `GetPSDisp` use different locks. Simply polling before/after and tagging current generation does **not** prove atomic association with the last accepted solution. Proposed interface exposes snapshot consistency and nullable solution epoch/capture. M2 must establish an epoch-fenced native snapshot/event handoff (or verified quiescent capture); a bracketed-only snapshot remains diagnostic and cannot claim a precise acquisition time. No-calibration/reset may leave display arrays present but scientifically invalid.

### Distortion Analyzer measurement definition

For tones `f1<f2`, compute lower/upper third order `(2f1−f2, 2f2−f1)`, fifth `(3f1−2f2, 3f2−2f1)`, seventh `(4f1−3f2, 4f2−3f1)`. Use integrated **linear power** around each fundamental/product, not the tallest bin and not an average of dB values. Default `dBc=10*log10(Pproduct/min(Ptone1,Ptone2))`; report both sides and the worse/larger resolved value. Never show a complete worst-of-pair score if one side is unavailable without labeling that limitation.

Record FFT size/rate/window/coherent gain/ENBW, bin spacing, integration regions, averaging count/capture duration, tone spacing/balance, usable filter passband, noise estimator, route/attenuation, clipping status and continuity. Peaks below the defensible detection threshold get an **upper bound** or null plus reason, not a fabricated −100dBc value. Beyond usable filter bandwidth means unavailable, not good suppression. A clipped fundamental/feedback capture invalidates the result. Unknown clipping evidence is explicitly limited diagnostic evidence, not a qualified IMD claim.

Optional PEP-relative results use `(sqrt(Ptone1)+sqrt(Ptone2))^2` as the ideal two-tone PEP-equivalent power reference. For equal tones this differs by6.0206dB from the single-tone reference. Do not convert digital power to calibrated watts or equate FPGA detector and LP700 readings. The prior short carrier/two-tone tests demonstrate guarded TX transport and operator observations, **not measured correction, absolute feedback calibration, or IMD**. No external RF spectrum measurement was supplied.

### Docking and authority

Add a PS tab next to TX as the single editable PS settings location; leave TX a compact enable/state/fault badge. Each panel supports Dock/Pop out, resize, remembered desktop layout and reset layout; blocked popups fall back in-page; mobile remains in-page. Popouts are authenticated read-only observers sharing telemetry, with no TX/control lease and no broadcast-channel authority bypass. Closing a panel never disables correction or keys/unkeys RF. Observer subscriptions must not keep an otherwise released controller lease alive. Separate internal-PA and external-amplifier profiles with verified feedback routes.
